# DeepVOG / TAPIR 검토와 실행 구현 — 2026-10-04

**지금 시험할 주 경로는 D + ECC (`orlosky-ecc`)다.** 두 공식 모델도 실제 가중치로 연결했지만,
첨부 영상에서 독립 검출기로 DeepVOG를 쓰거나 주변 기준을 TAPIR로 추적하는 것은 누락이 더 많았다.
모델 두 개를 붙이면 1→9→4가 해결된다는 근거는 없다. 현재 코드는 실행 가능하며,
실착용 4점 합격이나 여러 관람객에 대한 정확도 검증을 완료한 상태는 아니다.

범위는 `camera_accuracy`뿐이다. 부착 마커, 필수 반사점, 이 사용자의 고정 눈 크기를 추가하지 않았다.

## 두 저장소에서 가져온 것과 우리가 만든 것

| 경로 | 공식 구현/가중치 | 이 프로젝트의 구현 |
|---|---|---|
| DeepVOG | 원본 FCNN 그래프와 공식 HDF5 가중치, 동공 확률 채널 | Keras 3/PyTorch 실행 어댑터, 기존 가림 윤곽·타원 품질 검사, 로컬 서버/UI 연결 |
| TAPIR | 공식 Torch의 causal BootsTAPIR와 공식 체크포인트, query feature와 causal state | 착용자 기준 영상에서 눈 바깥 특징점 선택, 가시성·이동 동의 검사, 동공에서 이동 차감 |
| D + ECC | 기존 Orlosky/OpenCV 검출과 LK, OpenCV ECC | 중앙 1점 기준 저장, 영상 마스크, 고정 기준에 대한 상대 동공 좌표, 실패·수집 정책 |
| 화면 mapping | 기존 NumPy 9점 회귀 | 유지. 4점 모두 기준 0.12 이하일 때만 출력 활성화 |

[DeepVOG](https://github.com/pydsgz/DeepVOG)는 동공 분할과 오프라인 3D 시선 추정을 제공한다.
이 버전의 출력은 동공/비동공이며 홍채 분할기가 아니다. 원본 README의 3D 추정은 눈과 카메라의
상대 위치가 유지된다는 가정을 둔다. 이번 목적의 흔들림 보정기로 그 3D 부분을 그대로 쓰지 않았다.
그래프는 수정하지 않고 Keras 3의 Torch backend에서 공식 가중치를 읽는다. TensorFlow/JAX는 설치하지 않았다.
소스 고정: `2b8644c23e4472697c2a9949033b78af1f79e34e`, GPL-3.0, 원본 LICENSE를 함께 저장했다.

[TAP](https://github.com/google-deepmind/tapnet)는 지점 추적 알고리즘 계열이다.
동공·홍채의 의미를 찾거나 화면 시선을 계산하는 모델은 아니다. 실시간 입력에는 공식 online
causal BootsTAPIR의 Torch 경로만 연결했다. TAPNext/Transformer 학습 환경 전체를 들이지 않았다.
동공 주변의 이동에는 정상 안구 운동이 포함되므로 TAPIR가 추적한 동공 이동을 카메라 움직임이라고 빼지 않는다.
소스 고정: `730cda1c730877cfedbe01bf87fb1cadb78a565d`. 공식 저장소는 코드와 체크포인트를 Apache-2.0으로 명시한다.

## 이번에 고친 실제 동작

1. **중앙 1점이 실제 기준을 만든다.** 새 검출 12개 이상의 안정된 관측을 수집한 뒤 현재 사용자의
   영상과 주변 마스크를 저장한다. 마스크는 현재 동공 위치·크기에서 넓은 눈 영역을 제외하며,
   포화 반사도 제외한다. 반사점의 존재나 안경 착용을 요구하지 않는다.
2. **기준을 고정한다.** ECC 또는 TAPIR의 이동이 유효할 때만 `현재 동공 − 기준 대비 이동`을 회귀에 넣는다.
   순간 가림 때 오래된 이동을 계속 빼거나 기준을 몰래 새 영상으로 바꾸지 않는다.
   같은 기준으로 재정합하며, 새 보정 시작·초기화는 이전 착용자의 기준을 지운다.
3. **ECC의 급격한 이동 대응.** 정합이 실패하면 기존 앞뒤 검사 LK가 같은 중앙 기준에 대해 이동을 제안한다.
   ECC가 그 제안을 재검증해야 출력한다. 누적 LK로 기준을 이동시키지 않는다.
4. **flow 보완 프레임은 보정에서 제외한다.** D의 `verified_optical_flow`는 이제 `predicted=true`,
   `fresh_detector=false`다. 잠깐의 표시 연속성과 보정의 실제 경계 관측을 구분한다.
5. **표본이 모일 때까지 1.2–4초 수집한다.** 새 검출 12개와 p90 안정성 기준 0.08을 유지한다.
   초반 흔들림이 있으면 최근 12개가 안정된 구간을 선택하고 버린 초반 표본 수를 기록한다.
   마지막 프레임의 짧은 깜빡임만으로 좋은 표본을 버리지 않는다. 오래된 표본만 남으면 수집을 거절한다.
6. **느린 모델의 오래된 프레임을 거절한다.** 처리 완료 시각으로 프레임 나이를 덮어쓰지 않는다.
   OpenCV 반환 뒤 350ms를 넘긴 관측은 실시간 시선으로 출력하지 않는다.

기준 좌표는 320×240 센서 크기로 계산하고, 미리보기 타원은 기존 640×480 좌표로 유지한다.
TAPIR는 최대 16개 주변 특징점을 사용하고, 공식 가시성 확률 및 4개 이상/60% 이상 이동 동의,
공간 분포를 확인한다. 신뢰 조건을 풀어서 표본 수를 늘리지 않았다.

## 전체 첨부 영상의 실행 결과

`camera-01.avi`의 1,123프레임을 모두 재생했다. 기록의 보정 활성 여부를 재생하고, 이전 연구와 같은
두 번째 중앙 주시의 560번 영상을 기준으로 삼았다. 목표 잔차로 기준 영상이나 마스크를 선택하지 않았다.
기록 시작 전 이력과 원래 tracker의 모든 reset/seed 상태를 완전히 복원한 재생은 아니다.

| 경로 | 품질 기준 통과 / 1,123 | 그중 새 검출 | 전체 재생 중앙 처리 시간 |
|---|---:|---:|---:|
| D | 1,017 | 937 | 7.3ms |
| D + ECC | 1,012 | 932 | 8.2ms |
| DeepVOG | 656 | 656 | 111.6ms, MPS |
| DeepVOG + ECC | 656 | 656 | 145.2ms, MPS |
| D + online BootsTAPIR | 641 | 588 | 141.5ms, MPS/일부 CPU fallback |

이 수치는 **정확도·recall이 아니다.** 사람별 모델 confidence의 의미가 다르며 정답 동공/홍채 라벨이 없다.
이동 보정 경로의 시간에는 기준 설정 전의 가벼운 검출 구간도 포함된다. 최종 ECC의 별도 CPU 재생은
중앙 22.0ms, p95 33.2ms였다. Torch 초기화·동시 실행·thread 설정에 따라 차이가 난다.
CPU 모델 실행은 DeepVOG/TAPIR 모두 약 1–2초/프레임이어서 현재 실시간 경로에는 맞지 않았다.

기준 설정 이후 562프레임에서 주변 이동을 확보한 수는 ECC **534**, TAPIR **133**이었다.
TAPIR는 이 근접 흑백 눈 영상에서 가시성/동의 조건을 자주 통과하지 못했다.
DeepVOG는 일부 방향에서 분할이 커지거나 후보가 없어져 새 검출이 부족했다. 기본 검출기를 대체하지 않는다.
DeepVOG를 D의 flow 실패 때만 보조하는 오프라인 조합도 검사했지만, 부족한 8번째 목표 표본을 채우지 못해
복합 실시간 경로는 추가하지 않았다.

최종 ECC 재생에서 두 번째 9점의 새 검출 수는 **24, 24, 22, 22, 24, 23, 18, 5, 24**였다.
8번째 목표는 표본 수뿐 아니라 약 28 센서 px의 산포가 있었다. 원래 1.2초 창을 그대로 쓰면
이번 경로도 이 지점에서 합격하지 않는다. 나머지 8점의 수집 구간 p90 산포는 D의 약 **1.75–4.26px**에서
ECC의 **0.87–1.91px**로 줄었다. 정상 안구 운동과 검출 오차도 섞인 관측 산포이며 시선 정확도는 아니다.

이전 문서의 ECC 학습 잔차 0.054는 **녹화된 동공을 재사용하고 flow 보완 표본도 포함한 진단**이었다.
이번 새 검출 분리 재생을 그 수치로 합격 처리하지 않았다. 9점의 부족한 표본은 더 오래 올바르게 바라본
실제 새 입력에서 수집해야 하며, 녹화에는 독립 4점이 없다.

원자료: [5개 경로 전체 출력](diagnostics/markerless/research-replay-20261004.json),
[최종 ECC 재생](diagnostics/markerless/ecc-replay-20261004.json).
기록의 reset 두 곳(22·392번 프레임)을 추가로 반영한 [D/ECC 재생](diagnostics/markerless/reset-replay-20261004.json)에서도
8번째 목표의 새 검출은 5개여서 실패했다. 초기화 이력을 반영하는 것만으로 이 누락이 해결되지는 않았다.

## 실행과 재현

현재 Mac에는 공식 모델과 필요한 패키지를 설치했다. 가중치 약 303MB는 Git에서 제외한 `models/`에 두며,
설치/실행 시 SHA-256을 검증한다. 새 환경에서는 기존 detector 설치 후 다음을 실행한다.

```bash
camera_accuracy/.venv/bin/python -m camera_accuracy.install_research
bash camera_accuracy/start.sh --engine orlosky-ecc
```

화면에서 `D + 착용자 기준 보정 (ECC)`를 선택한 뒤 **1→9→4**를 진행한다.
DeepVOG/TAPIR도 검출기 목록에서 설정 적용으로 교체할 수 있다. 모델 교체는 보정을 초기화한다.
기본 원본 비교 경로는 유지하고, 권장 새 경로를 위 명령으로 명시한다.

이번 작업에서는 USB 장치 목록이 비어 있었다. `http://localhost:8090`에 첨부 영상 재생 화면을 열어
미리보기와 검출기 선택을 확인했다. 이 재생 모드는 실제 보정 시작을 차단한다.
재생 서버를 유지하면서 연결한 USB를 시험하려면 별도 포트를 사용한다.

```bash
bash camera_accuracy/start.sh --engine orlosky-ecc --port 8091
```

전체 비교 재현:

```bash
PYTORCH_ENABLE_MPS_FALLBACK=1 KERAS_BACKEND=torch \
camera_accuracy/.venv/bin/python -m camera_accuracy.compare_detectors \
  --video /Users/chanwoo/Downloads/20261002T071853Z-0058e7f6/camera-01.avi \
  --frames 1123 --recorded-state --reference-frame 560 \
  --engines orlosky-flow orlosky-ecc deepvog deepvog-ecc orlosky-tapir \
  --output /tmp/research-replay.json
```

회귀 검사: `camera_accuracy/.venv/bin/python -m unittest camera_accuracy.test_accuracy -v`. **15개 모두 통과했다.**
새 검출만 수집하기, 마지막 깜빡임, 초반 흔들림 뒤 안정 구간 선택, 늦은 처리 거절,
착용자 기준 수집/재설정, 알려진 카메라 이동 제거와 실제 눈 움직임 보존을 포함한다.

## 남는 한계와 다음 실착용 검사

- 이 구현의 주변 마스크는 피부/안경의 의미 분할이 아니다. 눈 크기로 넓게 제외하는 근사이며
  안경 렌즈나 움직이는 눈꺼풀 일부가 남을 수 있다. 현재 사용자에게서 무늬·정합 품질을 확인하고 실패를 거절한다.
- 평행이동 보정이다. 카메라 roll, 큰 거리 변화, 재착용은 새 1→9→4가 필요하다.
  눈 카메라만으로 화면에 대한 머리의 모든 움직임을 알아내지는 못한다.
- 동공/홍채 픽셀 정답이 없으므로 경계 정확도를 검증한 것은 아니다. DeepVOG가 홍채 검사를 제공한다고 해석하지 않는다.
- 실제 USB에서 먼저 새 경로의 9점/독립 4점을 기록하고, 안경 유무와 서로 다른 관람객으로 성공률,
  누락, 고정 주시 산포, 작은 착용 이동 전후 오차를 확인한다. 이 관측 없이 전시용으로 완성됐다고 주장하지 않는다.
