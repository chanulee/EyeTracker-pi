녹화 AVI를 디코딩한 동일 760프레임을 각 검출기에 입력했습니다. PuReST는 설치된 PyPupilEXT의 전체 영상 `run(gray)`를 사용했습니다.

## 4. Orlosky 코드의 불안정성이 생기는 지점

- **전체 프레임에서 가장 어두운 작은 영역을 매 프레임 다시 찾음.** 직전 동공 위치를 사용하지 않아 속눈썹·눈꺼풀·홍채의 다른 부분으로 탐색 출발점이 바뀔 수 있습니다.
- **그 영역의 밝기 +5/+15/+25, headless에서는 +40으로 이진화.** 밝기 변화에 따라 동공과 홍채가 연결되거나 반사점 때문에 끊어집니다.
- **5×5 dilation을 두 번 하고 조건을 만족하는 가장 큰 윤곽을 선택.** 작은 경계 차이를 메우지만 홍채/눈꺼풀과 합쳐지는 후보도 생깁니다. native 320×240를 640×480으로 확대해도 원래 없던 경계 정보는 복구되지 않습니다.
- **confidence는 채워진 윤곽과 타원의 Dice 겹침.** 동공인지 검사하는 점수가 아닙니다. 큰 홍채나 가려진 어두운 덩어리도 높은 점수가 될 수 있습니다.
- **윤곽 정리 뒤 타원을 다시 맞추지만 방향 계산은 정리 전의 정수 중심을 사용.** 표시와 실제 입력이 다릅니다. 이 실제 영상의 첫 120프레임 중 검출된 119프레임에서 두 중심 차이는 중앙값 1.29, 최대 3.96 처리 px였습니다. `orlosky-center-consistency.json`으로 재현했습니다. 정답 대비 검출 오차와 구분해야 합니다.
- **눈 중심은 여러 타원의 축 방향 선을 2D에서 교차시켜 추정.** 매번 최대 네 타원을 랜덤 선택합니다. 거의 원형인 타원은 축 방향이 불안정하고, 영상상의 축 직선을 진짜 3D 동공 법선으로 취급할 수 없습니다.
- **3D 변환은 실제 카메라를 보정한 모델이 아님.** 시야각 45°, 카메라 z=3, 구 반경 1/1.05, 눈 중심 배율 1.5를 고정합니다. 표시하는 적응 반경은 이 방향 계산에 쓰이지 않습니다.
- **화면 출력은 direction의 x/y를 다시 9점 회귀에 넣음.** 현재는 카메라/화면의 실측 외부 파라미터로 광선을 화면 평면에 교차시키는 구조가 아닙니다.

따라서 코드는 이미 구와 벡터를 사용하지만, 물리적으로 맞는 3D 모델이라는 증거는 없습니다. 현재 셋업에서는 동공 후보와 눈 중심의 편향이 이 가상 변환을 거쳐 증폭될 여지가 있습니다.

## 5. 2D·3D와 전체 홍채 추적

2D는 동공의 영상 좌표 `(u,v)`를 화면 좌표로 보정합니다. 카메라·눈·화면 위치가 고정돼 있으면 충분히 작동할 수 있습니다. 카메라가 움직여 생긴 영상 좌표 변화와 안구 회전으로 생긴 변화를 분리하기 어렵습니다.

3D는 카메라 내부 파라미터와 동공 타원의 중심·장축·단축·각도, 여러 시점의 관측을 이용해 눈 중심과 동공 원판의 위치/법선을 추정합니다. 개념적으로 `d = normalize(P_3D - C_eye)`에 해당합니다. **영상의 동공 중심은 2D 투영점**이므로 이것과 3D 구 중심을 바로 연결해서는 깊이를 알 수 없습니다. 광학축과 실제 시선축의 차이, 화면 위치도 보정해야 합니다. [Świrski & Dodgson](https://www.cl.cam.ac.uk/research/rainbow/projects/eyemodelfit/)와 [pye3d](https://docs.pupil-labs.com/core/developer/pye3d/)가 기존 구현을 제공합니다.

전체 홍채 추적은 이전 후보를 유지하거나 홍채 바깥 경계의 타원 형태를 이용하는 데 유용할 수 있습니다. CSRT/KCF 같은 일반 객체 추적기의 사각형 중심만으로는 안구의 회전각이나 화면 주시점을 복원하지 않습니다. 눈꺼풀로 홍채가 가려질 때 보이는 영역의 중심도 바뀝니다. 홍채와 동공은 함께 회전하므로 홍채 이동을 통째로 빼면 실제 시선 이동까지 제거할 위험이 있습니다. 카메라 이동의 기준은 별도로 관측 가능한 눈 주변의 비교적 고정된 특징이어야 하며, 이 역시 표정·원근 변화에 한계가 있습니다.

중앙 2×2/전체 4×4 가정은 초기 ROI `(0.25,0.25,0.75,0.75)`와 후보 우선순위로 적절합니다. 추적 중에는 직전 동공 주변을 찾고 실패하면 탐색 범위를 넓히는 방식이 좋습니다. 실제 로그의 유효 후보 676개 중 해당 중앙 영역 밖은 2개뿐이고, 실패한 아홉 목표의 중앙값은 모두 안에 있습니다. 이 가정은 큰 오검출을 줄이지만 이번 입력 겹침을 해결하지는 못합니다. 현재 Orlosky 비교 엔진에는 ROI 적용이 아직 없습니다.

## 6. 제안하는 세 개발 방향

### A. Orlosky 검출 유지 + 시간적 일관성 — 우선 권장

1. 초기 중앙 ROI와 직전 동공 주변 탐색, 소실 시 점진적 재검색을 적용합니다. 크롭/확대 대신 마스크를 사용해 좌표계를 유지합니다.
2. 최종 실수 타원 중심을 검출·품질·방향에 일관되게 사용합니다. 모든 후보를 대상으로 실제 동공 크기, 경계 안팎 대비, 가림, 직전 위치·축 변화로 선택합니다.
3. [OpenCV Lucas–Kanade](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html)는 프레임 사이의 후보 위치 예측에만 사용합니다. 전후 방향 추적 오차와 특징점 수를 검사하고, 소실/깜빡임 때 다시 검출합니다. 예측만으로 채운 좌표를 calibration의 관측 표본으로 넣지 않습니다. IR 반사점은 고정된 표면 특징점으로 취급하지 않습니다.
4. [CLAHE](https://docs.opencv.org/4.x/d5/daf/tutorial_py_histogram_equalization.html)는 약하게 적용한 별도 실험으로 비교합니다. 없어진 대비·초점을 만들 수 없고 노이즈와 홍채 무늬도 증폭할 수 있어 기존 threshold를 그대로 쓰면 후보가 바뀔 수 있습니다. 전체 눈 영상은 퍼져 보여 초점/카메라 거리/실제 해상도 확인도 병행합니다.

[RITnet 원 논문](https://arxiv.org/html/1910.00694v1)은 동공·홍채 구분을 위한 전처리로 gamma 0.8과 CLAHE 8×8 / clip limit 1.5를 사용합니다. 이미 연구된 실험 출발점이지만 이 카메라의 최적값이라는 뜻은 아닙니다. 경계 검출기의 threshold와 함께 원본/전처리를 같은 프레임에서 비교해야 합니다.

[PuReST 논문](https://www.hci.uni-tuebingen.de/assets/pdf/publications/TWE062018.pdf)은 이전 동공의 위치·모양을 이용해 추적하고 실패하면 재검출하는 접근을 제시합니다. 이미 설치된 PyPupilEXT에서 실행까지 확인했습니다. 이는 새 전체 알고리즘을 작성할 필요가 없다는 근거입니다. 다만 [현재 공개 ROI overload](https://github.com/openPupil/PyPupilEXT/blob/main/src/pupil-detection-methods/PuReST.cpp#L77)에는 최소/최대 지름 인자 전달이 의심되는 코드가 있어 ROI/크기 옵션까지 그대로 신뢰하지 않습니다. 이번 시험은 전체 영상 overload를 사용했습니다.

성공 기준: 같은 주시 중 높은 confidence의 후보 점프가 줄고 수작업 표식 대비 중심/윤곽 오차가 감소하며, 새 반복의 독립 4점 화면 오차도 감소하는 것. 부드러움이나 후보 수만으로 채택하지 않습니다.

### B. 안정된 Orlosky 타원 + 실측 pye3d — 움직임 대응의 다음 단계

검출부를 유지하고 임의의 구 변환만 기존 pye3d 모델로 교체합니다. 실제 사용할 해상도·초점 설정에서 카메라 초점거리/주점/왜곡을 측정하고 크롭/확대 좌표 변환을 반영해야 합니다. Dice를 Pupil Labs의 confidence와 같은 의미로 전달하면 안 되므로 후보 품질·가림 검사도 먼저 필요합니다.

여러 방향의 타원으로 눈 모델을 준비하고 모델의 안정성/재투영 오차를 확인합니다. 화면 보정 중 입력 좌표계를 일정하게 유지하고, 완료 뒤의 모델 적응은 미끄러짐 실험에서 따로 평가합니다. 현재 준비 표본 수만 충족하는 검사를 신뢰도 검증으로 대신하지 않습니다.

눈-카메라의 상대 이동과 머리-화면의 이동을 나눕니다. 화면에 대한 머리의 자유 움직임까지 필요하면 화면 마커/장면 카메라/추가 자세 기준이 필요합니다. 이미 구현된 Pupil Labs 수학 모델과 보정 코드를 재사용하는 통합 작업이며 새 3D 이론을 만들 필요는 없습니다.

성공 기준: 고정 상태의 오차를 악화시키지 않고, 통제된 카메라 미끄러짐 후 독립 검증 오차가 줄어드는 것. 눈 카메라 한 대의 모델만으로 전체 머리 움직임 보정을 주장하지 않습니다.

### C. 사전학습 동공·홍채 분할 — 대비 문제가 남을 때

동공과 홍채를 의미적으로 구분하는 [RITnet](https://arxiv.org/abs/1910.00694)의 사전학습 모델 또는 동공 분할용 [MEYE](https://github.com/fabiocarrara/meye)를 오프라인 비교합니다. 후자는 홍채까지 자동으로 구분한다고 가정하지 않습니다. [GC0308을 사용한 MEYELens 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC13498615/)도 있어 동일 센서 계열에서 검토할 근거가 있습니다.

분할 마스크에서 실제 동공 윤곽을 추출해 기존 2D 회귀 또는 pye3d로 연결합니다. 기존 모델이 이 카메라의 흐릿함·가림을 처리하는지 확인한 뒤에만 소규모 추가 표식/미세 조정을 고려합니다. 원본에 경계 정보가 없으면 신경망도 복구를 보장하지 않습니다. 처음부터 학습 모델을 만들 필요는 없습니다.

성공 기준: 실제 주시 방향·깜빡임·반사광을 포함한 별도 영상에서 동공/홍채 혼동과 윤곽 오차가 A보다 감소하며 실시간 처리 비용을 감당하는 것. 공개 데이터셋 성능을 이 사용자/GC0308의 성능으로 옮겨 주장하지 않습니다.

## 7. 공통 실험 조건과 이번 수정 범위

우선 렌즈 초점과 동공 경계가 실제 native 영상에서 보이는지 확인합니다. USB 케이블 장력을 풀고 지지대를 고정하며, 아홉 방향에서 눈꺼풀 가림을 확인합니다. 노출·조명·배경 밝기를 실험 중 일정하게 유지합니다. LED 밝기와 영상 밝기는 별개이고, 사용자 보드의 IR 제어 방식은 아직 확인되지 않았습니다.

[Pupil Labs 개발자 토론](https://chat-archive.pupil-labs.com/logs/core/2022/03/)에도 낮은 동공-홍채 대비와 ROI/노출/크기 조절 문제가 보고돼 있습니다. 특정 민족/눈 색만의 문제로 단정하지 않습니다.

이번에는 새 안정화 알고리즘을 임의로 켜지 않았습니다. 기본 실행 검출기를 Orlosky로 복귀하고, 입력 소스를 화면 위에 명시하며, 영상 파일 모드에서 실제 보정을 차단했습니다. 9점 회귀 실패에는 전체 오차와 최악 목표 번호·9점 재시작 안내를 추가했습니다. 임계값/회귀/Orlosky 원본 파일은 변경하지 않았습니다. 변경된 동작을 포함한 자동 검사 7개가 통과했습니다.

다음 개발 순서는 **A로 검출 신뢰성을 확보 → 같은 관측으로 2D와 B를 대조 → 대비 때문에 A가 실패하면 C**입니다. 알고리즘 선택에 사용한 보정/검증 자료와 최종 평가 반복을 구분해야 합니다. 기존 PyPupilEXT/PuReST 등의 버전별 라이선스 조건은 운영 편입 전에 확인합니다.
