# 확인 결과 · 2026-10-07

Mac에서 확인한 결과입니다. 실제 Pi를 착용한 전시장 성능 측정과 구분합니다.

연결 검사는 실제 로컬 HTTP/WebSocket을 사용합니다. 인증 없는 카메라 연결(401), 카메라 중복 연결(409), 다른 Origin의 보정 요청(403), 2P 장치 경로(404)를 확인했습니다. 검은 JPEG를 실제 Orlosky 추정기에 전달해 영상 수신을 확인하고, 연결 해제 시 이전 관람객 보정값이 초기화되는지도 검사했습니다.

시선 보정 수학과 전체 경로 검사는 모의 방향을 사용했습니다. 350 ms 이상 지난 시선의 무효화, 센서 연결 손실·재연결, 나뉘어 도착하는 SSE/PCM, PCM 16 kHz S16_LE 형식과 제한된 큐, 발화 종료 후 음성 구독 해제를 확인했습니다. 모의 테스트 톤은 실제 한국어 인식 품질을 검증하지 않습니다.

## 현재 연결된 USB 카메라

Mac의 장치 목록을 다시 조회해 USB Camera 1대를 확인했습니다. 기존 `camera_accuracy` 서버의 장치 새로고침 후 정체된 캡처를 재시작했고, 320×240 영상과 증가하는 프레임 번호, 약 7 FPS, 약 151 ms 프레임 나이를 확인했습니다. 이 서버는 기존 DeepVOG 실험 설정을 유지합니다. 해당 확인 시점에는 동공 검출·착용 보정이 완료되지 않았습니다.

`final/`의 기본 추정기는 기존 운영용 Orlosky입니다. 위 USB 캡처 확인은 Pi에서 송신하는 전시용 카메라의 성능 검증을 대신하지 않습니다.

## 현장에서 남은 확인

1. Pi에 이 폴더를 설치하고 카메라·IMU·I2S 마이크를 동시에 연결합니다.
2. Mac 영상 수신 주소·토큰과 `PI_SENSOR_URL_1`을 실제 장비 주소로 설정합니다.
3. 최종 화면 크기와 착용 자세로 1P의 9점 보정·3점 검증을 수행하고, 응시 선택 정확도를 확인합니다.
4. IMU 장착 축·방향·정면 기준, Pi 말소리 인식, 현장 Wi-Fi 지연을 확인합니다.
5. Pi 재부팅·케이블 분리·재연결 후 서비스 복구와 새 관람객 재보정을 확인합니다.
